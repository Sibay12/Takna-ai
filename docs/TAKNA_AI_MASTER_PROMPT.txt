Mandatory isolation rules:

1. Maintain an explicit allowlist of TAKNA AI collection names.
2. Validate collection names before creating collections or indexes.
3. Reject application collection names that do not begin with "ai_".
4. Never operate on arbitrary collections merely because they share the prefix.
5. Never call "dropDatabase()" in application startup, migrations, or cleanup scripts.
6. Never drop or recreate existing collections to initialize the application.
7. Never run unrestricted database-wide cleanup.
8. Never alter other projects' indexes, documents, collections, or retention policies.
9. Never assume that a collection beginning with "ai_" necessarily belongs to TAKNA AI if another project could use the same prefix.
10. Use explicit database configuration and fail safely if it is missing or invalid.
11. Scope every migration, TTL index, cleanup job, and database query to the intended database and approved collection.
12. Prefer a separate "takna_ai" database and dedicated database user if the existing MongoDB deployment permits it.
13. If a shared database must be used, preserve its existing data and restrict all application operations to the explicitly approved TAKNA AI collections.
14. Use least-privilege database permissions. Do not use unrestricted server administrator credentials for routine application requests.

All startup scripts must be idempotent and non-destructive.

15. AUTOMATIC SEVEN-DAY CHAT DELETION
==================================================

Mandatory rule:

Every stored chat message must expire seven days after its individual creation timestamp.

This rule applies equally to Free and Premium users.

Use:

- "ai_messages"
- "ai_conversations"

Each message must contain:

- "_id"
- "ownerId"
- "conversationId"
- "role"
- "content"
- "createdAt"
- "expiresAt"

Calculate:

"expiresAt = createdAt + 7 days"

Every new message gets its own expiration timestamp.

Do not reset existing messages' expiration when a new message is added.

Each conversation record must also have an explicit seven-day expiration policy.

Create MongoDB TTL indexes on "expiresAt" with "expireAfterSeconds: 0" for the approved collections.

Use idempotent index initialization.

API-level retention enforcement is mandatory because MongoDB TTL deletion is asynchronous.

Requirements:

- Exclude expired messages from history APIs.
- Exclude expired conversations from lists.
- Reject access to expired history.
- Verify resource ownership.
- Clear expired cached history.
- Prevent exports and analytics from retaining expired message content.
- Provide Delete Chat Now.
- Confirm backend deletion before reporting success.

Add retention monitoring and safe cleanup verification.

Do not rely solely on Render staying awake.

Do not preserve full conversation content in permanent logs, audit records, support tickets or analytics.

The Admin Panel must display the seven-day policy, TTL index status and cleanup verification.

Ordinary administrators must not be able to disable the mandatory retention rule.

Document provider-side and backup retention separately. Do not claim immediate erasure from every backup unless it is actually guaranteed.

Test expiry timestamps, TTL indexes, API access restrictions, early deletion and cleanup retries.
